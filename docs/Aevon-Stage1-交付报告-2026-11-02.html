本期交付了什么

三件事，互相独立

① 完整设置面

8 个面板、64 个设置项，键名与母本逐字一致（SISI、RTSIF、SSInterceptor…）。

04

手机实测流程

全程图形界面，不需要终端

装之前：确认一件事

你的越狱是 rootless（有 /var/jb 目录）。本包所有文件都落在 /var/jb 下， 不写 /System、不装 LaunchDaemon、不动 /usr/lib——这也是「最坏只会掉桌面，不会开不了机」的物理原因。

  • 用 Filza 打开 deb → 安装，或 Sileo 直接装
  • 装完 dpkg 不会重启桌面，此时插件尚未加载

重启预算：最多 3 次

正常验收 1 次；要演练 G0 逃生通道再加 2 次。每一次都会说明为什么必须重启。

  • 第 1 次：让 dylib 进桌面（必需）
  • 第 2 次：验证 G0 真能停用（可选）
  • 第 3 次：验证 G0 关掉后能回来（可选）
01

先看设置里有没有入口（不用重启）

打开「设置」，往下翻或直接搜索 Aevon。PreferenceLoader 是实时扫目录的，装完立刻就能看到。

应看到一行 Aevon，点进去是「状态 / 安全闸门 / 诊断 / 功能设置」。
看不到：设置 App 完全退出再进一次。仍没有 → 用 Filza 确认 /var/jb/Library/PreferenceLoader/Preferences/Aevon.plist 存在，把结果告诉我。
02

重启桌面一次 第 1 次重启

用越狱工具自带的重启按钮最稳。也可以点设置里的「重载桌面（应用闸门变更）」。

回来后进设置 → Aevon：注入状态 = 运行中，版本 = 0.1.0，启动次数 = 1，最近一次加载有时间。
状态显示「未加载」或启动次数为空：dylib 没被注入。先确认 G0/G1 是关的，再把 Aevon.plist 过滤器内容告诉我。
03

跑探针（这是本期最关键的一步）

点「重新探测（不重启）」→ 约 1.2 秒后弹「探测完成」，再点「查看探测报告」。

报告应含五段：环境 / 承载模型·方法签名 / 谁定义了这些方法 / 场景树 / 判定。 其中方法签名和场景树，正是 P1 开工前必须拿到的两项取证。
提示「没有响应」= 桌面里没有 Aevon 在跑（G0/G1 开着）。关掉闸门、重启桌面后再点一次。
04

点一遍 8 个面板

依次进「窗口与场景 / 承载形状 / 手势与动效 / 键盘与输入 / 通知 / 跳转与伪装 / 监听与系统动作 / 应用与全局」， 拨 2～3 个开关、拖 1 个滑杆，返回再进一次。

页面能正常打开、不闪退，改动返回后仍在（说明写盘成功）。这一步验证的是界面与存储，不是功能。
某个面板白屏或点进去闪退：先用 Filza 删掉 /var/jb/Library/PreferenceLoader/Preferences/Aevon.plist， 入口立刻消失，注入不受影响；然后把是哪个面板告诉我。
05

演练 G0 逃生通道 第 2 次重启

打开「紧急停止（G0）」→ 重启桌面。

回来状态变成 已紧急停止（G0）；点「重新探测」会提示没有响应——这是对的，它确实没在跑了。 桌面本身、其他插件、越狱环境全部正常。
如果重启后桌面异常：这说明问题不在 Aevon（它没加载）。直接进设置关掉 G0 即可。
06

关掉 G0，确认能回来 第 3 次重启

关掉「紧急停止（G0）」→ 重启桌面。

状态回到 运行中，启动次数 +1。至此闸门闭环验证完毕。
此时设置里的「重载桌面」可能无效——因为 Aevon 没加载，没人接这个请求，而设置进程又被沙箱限制执行外部命令。请改用越狱工具的重启按钮，这不是 bug。

不要主动测 G2（崩溃循环断路器）。它需要人为制造 3 次崩溃，风险与收益不成比例； 逻辑上它由「加载即计数 / 活过 60 秒清零 / 5 分钟内 3 次失败即永久停用 / 状态写不进去就干脆不加载」四条构成， 其中最后一条是 fail-safe：宁可不动，也不冒无法计数的险。

05

安全边界

这些是机械可验证的，不是承诺

三道闸门

  • G0 紧急停止：设置里一个开关，写入偏好 + 落一个文件，二者任一生效
  • G1 暂停注入：同上，带停用原因与时间
  • G2 崩溃断路器：3 次不稳定加载即自禁用；无法计数时直接不加载

闸门只影响「下次加载」。这是刻意的——运行时突然自我拆除比崩溃更难排查。

包里到底装了什么

  • Aevon.dylib 203,008 B —— 零钩子，只有闸门与探针
  • Aevon.plist 93 B —— 只注入 SpringBoard 一个进程
  • AevonPrefs.bundle 11 个文件 —— 设置界面
  • PreferenceLoader 入口 1 个
  • usr/libexec/aevon/ 4 个救援脚本（可选，不用终端也能操作）
红线为什么谁来守
不装 LaunchDaemon开机自启的守护进程才是真正能卡开机的东西CI 审计闸门
不写 /System、/usr/lib系统分区被改动，出问题只能刷机CI 审计闸门
postinst 不重启桌面安装即生效就没有反悔窗口脚本审查
注入范围只有 1 个进程扩大范围等于扩大崩溃面，必须是刻意动作CI 审计闸门
钩子必须写在闸门之后否则停用开关形同虚设代码约定

CI 审计闸门是白名单机制：包内多出任何一个文件、落点越界、注入目标多于一个，构建直接失败，坏包到不了手机。
