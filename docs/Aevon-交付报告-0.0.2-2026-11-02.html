01

环境切换：为什么必须重打包

不是换个参数，是换了安装位置

roothide 的 bootstrap 不在 /var/jb，而在 /var/containers/Bundle/Application/.jbroot-XXXXXXXXXXXXXXXX， 每次越狱随机。原先打的 rootless 包路径前缀是写死的，装上去会落到错的树里。

项目上一版 0.1.0（rootless）本版 0.0.2（roothide）依据
打包方案THEOS_PACKAGE_SCHEME=rootlessTHEOS_PACKAGE_SCHEME=roothideroothide 官方开发者文档：make package THEOS_PACKAGE_SCHEME=roothide
包内路径var/jb/Library/…Library/…roothide 包结构与 rootful 相同，由 dpkg 自己写进随机 jbroot
Architectureiphoneos-arm64iphoneos-arm64eroothide 的包标识，Sileo 用它判断能否安装
二进制切片arm64 + arm64earm64e手机是 arm64e，roothide 要求 arm64e
工具链theos/theosroothide/theos原版 theos 没有 roothide 打包规则
状态文件位置Library/Preferences/com.aevon.state.plistLibrary/Logs/Aevon/state.plistroothide 会把 Preferences 重定向到随机路径，Settings 与桌面可能读到不同副本

04

安全闸门

本轮新增 3 条机械校验
闸门机制为什么可靠
G0设置里的「紧急停止」开关写偏好域 com.aevon.aevon，桌面侧读取；不依赖终端、不依赖文件权限
G1「暂停注入」开关同上，并记录停用原因与时间
G2崩溃循环断路器活过 60 秒清零计数；5 分钟内连挂 3 次永久自禁用；状态文件写不进就不加载（fail-safe）
G3CI 包体审计见下三条；任一不过，构建红，包到不了你手机
G4阶段闸门每期都要真机验收，不过不开下一期

本轮新增的三条

  • 载荷只要出现 var/jb/ 前缀 → 失败（说明 scheme 没生效）
  • 两个 Mach-O 任一不含 arm64e 切片 → 失败
  • control 里出现 Description: → 失败（Sileo 会显示描述）

仍然守着的红线

  • 不装 LaunchDaemon / LaunchAgent
  • 不写 /System、不碰 substrate 本体
  • postinst 不重启桌面，激活永远由你手动触发
  • 过滤 plist 只允许注入 SpringBoard 一个进程
05

手机实测流程

全程只用设置 App，不需要终端

目标：用最少的重启次数，把「注入通了 / 闸门真的管用 / 设置能点」三件事一次验完。 标 重启 的步骤才需要重启桌面，其余都要重启后才会动。

1

装包，先别重启

在 Sileo / Zebra 里直接打开 com.aevon.aevon_0.0.2_iphoneos-arm64e.deb 安装。装完不要点任何"重启"。

期望：安装过程没有报错，也没有"依赖缺失"。装完桌面没有任何变化——这是对的，因为 postinst 故意不重启。
失败：Sileo 提示架构不匹配 → 把提示原文发我；提示依赖 ellekit 缺失 → 先装 ElleKit，再装本包。
2

确认设置里出现了「Aevon」不重启

打开 设置，往下翻，应该在越狱插件的区域看到一行 Aevon，点进去能看到「状态 / 安全闸门 / 诊断 / 功能设置」四组。

期望：入口在，8 个面板都能点进去，不闪退。此时状态显示"未加载"是正常的——桌面还没重新加载。
失败：看不到入口 → 设置 App 完全退出再进一次；仍没有 → 告诉我，我用 Filza 路径排查。某个面板点进去白屏/闪退 → 立刻在 Filza 删掉 …/Library/PreferenceLoader/Preferences/Aevon.plist，入口会消失，桌面行为不变，然后告诉我崩的是哪个面板。
3

重载桌面，验证注入重启 1

用越狱工具自带的重启按钮，或设置里 Aevon →「重载桌面（应用闸门变更）」。

期望：回到设置 → Aevon：注入状态 = 运行中，版本 = 0.0.2，启动次数 = 1，最近一次加载有时间。60 秒后再进来，启动次数变回 0（说明心跳清零生效）。
失败：状态一直是"未加载" → 注入没生效，把「诊断 → 查看探测报告」的内容发我（报告里有 jbroot 路径、各方法签名、场景树，一次就能定位）。
4

跑探针，把 P1 的两项取证一次拿全不重启

设置 → Aevon →「重新探测（不重启）」，等 2 秒，然后「查看探测报告」。

期望：报告第一段显示 越狱根 = .jbroot-…（roothide），然后能看到 _scene:interceptUpdateWithNewSettings: 的类型编码、哪些类直接实现了它、以及当前场景树（几个场景、每个场景几个窗口）。这三样齐了，P1 该怎么写就定了。
失败：提示"没有响应" → 说明桌面里没有 Aevon 在跑，回第 3 步。报告能看但没有场景树 → 把整份报告发我。
5

演练 G0 紧急停止重启 2

设置 → Aevon → 打开「紧急停止（G0）」，然后点「重载桌面」。

期望：桌面回来后，注入状态 = 已紧急停止（G0），版本停在 0.0.2 不再更新。这就是"出事时的那一键"，它必须真的管用。
失败：重启后仍显示"运行中" → 闸门没生效，立刻告诉我，这一条不通不能往下做功能。
6

关掉 G0，回到正常重启 3

关掉「紧急停止（G0）」，再点「重载桌面」。

期望：状态回到 运行中，启动次数重新开始计。到此为止，安全闭环验证完成。
失败：状态回不来 → 点「清除崩溃计数」再重载一次；仍不行就把探测报告发我。

只想快速看效果？

只做 第 1–4 步，只重启 1 次，就能拿到：注入是否正常、设置是否可用、P1 的两项取证。第 5–6 步是逃生通道演练，可以留到你方便的时候再做——但在开始写任何 hook 之前，它必须通过。
