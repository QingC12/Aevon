02

0.0.2 装了却看不到 Aevon：根因与修法

不是包坏了，是缓存

根因

「设置」进程在启动时会把 Library/PreferenceLoader/Preferences/ 读一遍，然后一直存在内存里。0.0.2 的 postinst 为了"不碰任何东西"， 连 Preferences 都没重启，于是：

  • 你装完时，设置其实还在用旧列表（没有 Aevon 那一行）
  • 它也不会自己退出：iOS 会把 Preferences 常驻
  • 所以"装成功了"和"看不到"同时成立

修法（两条腿）

  • postinst 结束后 killall -9 Preferences：只杀设置 App， 不动 SpringBoard，下次打开就是新列表
  • 入口 plist 与 bundle 信息补齐：isController=true、 CFBundleShortVersionString 与包版本一致、类名与 detail 完全对齐
  • 审计把这三者的自洽性变成构建闸门，以后不会再悄悄错位

顺带纠正一处旧数据的错误：0.0.2 的 bundle 里写着 CFBundleShortVersionString = 0.1.0， 而包版本是 0.0.2。现在三处（control / Swift 常量 / Info.plist）版本一致，CI 每次校验。

这一版做的减法

  • 文档提交不再构建：paths-ignore 挡住 docs/md/dist —— 省下的不是秒，是整次构建
  • theos/SDK 缓存：命中后 27 s 变 0 s
  • ldid 下载缓存：不再每次 brew install
  • 不跑 make clean：小工程没有收益，只有耗时
  • 连续 push 只留最后一次：concurrency

为什么不可能回到 60 秒以内

Swift 必须整模块编译，UIKit/Foundation 的模块加载本身就要几十秒， 这是语言的成本而不是配置的问题。稳态预期：命中缓存后 75–85 秒。 真正的节省在"不必要地触发构建"，那条已经堵住了。

06

真机实测流程（全在界面里，不需要终端）

按顺序做，每步都有"看到什么算过"
1

装包

Sileo 打开 com.Aevon_0.0.3-arm64e.deb 安装。 0.0.2 与 0.0.3 的包 id 不同，control 里带 Replaces/Conflicts，dpkg 会自动先卸旧包。

通过：安装结束没有报"文件冲突 / 依赖不满足"；终端输出最后一段是 Aevon 0.0.3 installed (roothide / arm64e / swift, zero hooks)。
不过：报 trying to overwrite ... com.aevon.aevon → 先在 Sileo 里手动卸载旧的 Aevon，再装一次。
2

打开设置，第一屏找 Aevon不重启桌面

装完不要重载桌面。直接打开「设置」，从第一屏往下看（如果你用 Shuffle 聚合，就去它给 Aevon 分的那组找）。

通过：能看到 Aevon 一行，点进去有「状态 / 安全闸门 / 功能设置 / 关于」。
不过：还没有 → 把设置从后台彻底划掉，再打开一次（这是进程缓存，不是包的问题）。仍然没有 → 把 sileo 的安装日志截图给我。
3

看状态区不重启桌面

「状态」里应有五行：注入状态 / 版本 / 启动次数 / 最近一次加载 / 日志文件。

通过：日志文件显示 /var/mobile/Aevon.log；注入状态是 未加载（还没重载桌面，这是对的）。
不过：日志行是空白或显示别的路径 → 说明装的是旧包，回到第 1 步确认版本。
4

第一次重载桌面桌面重启一次

点「重载桌面（应用闸门变更）」→ 确认。桌面会重启 5–10 秒。

通过：重新进设置，注入状态变成 运行中，版本 0.0.3，启动次数 ≥ 1；60 秒后再看，启动次数回到 0（心跳清计数）。
不过：状态一直是"未加载" → 桌面没加载 dylib：确认越狱是 roothide、ElleKit 在，然后把 Filza 里 /var/mobile/Aevon.log 的内容发我。
5

闸门 G0 / G1 双向验证每次都要重载

打开「紧急停止（G0）」→ 点「重载桌面」→ 回来看状态。

通过：状态变 已紧急停止（G0），桌面行为与没装时完全一样；关掉 G0 再重载 → 回到 运行中。G1 同样来回一次。
不过：开关拨了状态不变 → 是开关没有写进闸门，把状态截图发我（这一条是 0.0.3 必须过的安全底线）。
6

最后一条腿：文件闸门桌面重启一次

Filza 进 /var/mobile/Library/Logs/Aevon/，新建空文件 panic，然后重载桌面。

通过：状态变 已紧急停止（G0） —— 说明即使设置打不开，你也能用 Filza 停掉它。删掉 panic 再重载即恢复。
不过：建了文件仍显示运行中 → 文件没落在真实路径（可能建在 jbroot 里），换 /rootfs/var/mobile/Library/Logs/Aevon/ 再试。

第 4–6 步一共只会重启桌面 4 次；不需要重启设备，也不需要在电脑上做任何事。
