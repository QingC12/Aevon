01

先量，再画：GIF 里读到的三个数

证据/stheno图标动画.GIF

逆向文件夹里那段录屏是 295×639、522 帧、每帧 20 ms（约 10.4 秒）。我把它拆成帧， 对托盘区域的白色图标底盘做连通域检测，取三个不同位置的图标圆心做三点定圆：

量GIF 实测换算（393 pt 宽屏）
托盘半径R = 40.4 px≈ 54 pt —— 母本 Radius 默认 64，实际按自身 _scale 收缩
图标边长35 px（1225 px²）≈ 46 pt —— 与 IconWidth 默认 44 一致（含 1pt 抗锯齿边）
圆心位置(189.5, 566.9)屏幕右下角，即浮窗右下握把处 —— 不是屏幕中心
可见图标同帧检出 3 个白底其余图标底色是深色，未被阈值捕获；按 72° 均分推算，圆盘约 5–6 个

动画不是「沿弧淡入」

第 65–78 帧可以看到全部图标先聚成一个点，随后边外扩边放大、逐个错开落位。 这与 RingEnv 的 _offset 加弹簧模型完全吻合 —— 图标是从枢轴长出来的，不是从天上掉下来的。

所以第一版就按「绽放」写

起点 = 枢轴点、缩放 0.12、透明 0；终点 = 弧上落位、缩放 1、透明 1； 相邻错开 22 ms，弹簧阻尼取 DampingFraction。不是先做完再调，而是照着量到的东西写。

02

几何：四种形状，一条公式决定能放几个

RingModel.swift

角度约定全项目统一：0° 朝上（12 点），顺时针为正。下面的图是用同一套公式在本地算出来的落位， 不是示意图 —— 图标之间不重叠，靠的是容量公式而不是手调的间距。

形状母本键扫角起始角说明
圆盘RTSIF360°（闭合）旋转角首尾相接，按 360/n 均分，0° 不会落两个图标
半圆盘RTSIH180°旋转角 − 90°默认占上半圆：左右两端水平，贴边使用
直角盘RTSIQ90°旋转角 − 45°默认占正上方 90°，贴角展开
任意角度RTSIZ尾角 − 旋转角旋转角拖动即改尾角；两端差值小于 5° 时按闭合圆盘处理
 
// 相邻图标所需的最小圆心角：弦长 = 图标宽度 + 间距
step = 2 · asin( min(1, (iconWidth + 6) / (2 · radius)) )

// 闭合盘用整除，开口弧用「段数 + 1」——后者两端要各占一个图标
圆盘 / 任意闭合 : n = floor(2π / step)        // R64·44pt → 7
半圆 / 直角     : n = floor(扫角 / step) + 1  // → 4 / 2

这条公式同时解释了 GIF：把 R=54、图标 46 代进去得 6 个， 正是录屏里那个密度。母本的 _angleScale 允许在此基础上再做角度压缩，我们暂未接线。

04

承载的是谁：图标三级回退，并且把用了哪一级写在页面上

RingIcons.swift
1

LaunchServices首选

LSApplicationWorkspace 列出全部已安装 App，图标走 +[UIImage _applicationIconImageForBundleIdentifier:format:scale:] —— 这是桌面自己渲染图标用的方法， 连只有 Assets.car 的 App 也能拿到真实图标。调用前先 responds(to:) 判断，系统没有这个方法就跳过，不会变成崩溃。

2

文件扫描

/Applications 与 /var/containers/Bundle/Application 下逐个读 Info.plist 取名字与 bundle id， 图标找包内的 AppIcon60x60@2x.png 一类平铺文件。

3

占位色块

前两级都读不到时，按名字生成圆角色块加首字。颜色用稳定散列（String.hashValue 每次进程启动都不同，会让同一个 App 换色）。

关键是：用了哪一级会写在预览页第三行。空环或假环看起来像几何写错了，而几何正是这一版要评审的东西 —— 所以宁可把「读不到」说清楚。

05

为什么宿主先放在设置里，而不是桌面上

这是刻意的取舍，不是省事

放在设置里得到的

  • 装完不用重启就能看，改一个参数重开一次，迭代成本几乎为零
  • 桌面进程一行代码都没加，几何实验再离谱也不可能让手机起不来
  • 预览页就是调参面板：半径、图标宽度、四种形状都能当场对比

代价与偿还方式

  • 预览页的枢轴在屏幕中心，而母本在浮窗右下握把 —— 位置差别由下一步的宿主决定，形状本身不受影响
  • 点图标目前只弹名字，不打开 App —— 打开需要浮窗与场景，属于下一步
  • RingView 是纯叶子视图：不建窗口、不抢手势、不启动 App，换宿主不用改一行

真机验证流程

不需要终端，不需要重启
1

安装 com.Aevon_0.0.5-arm64e.deb

用 Filza 点开安装。装完设置 App 会自动重启（postinst 只杀 Preferences，不动桌面）。

预期：打开「设置」→ 插件集合 → 仍能看到 Aevon，根页 21 行不变。
2

进入「承载形状」面板

设置 → Aevon → 功能设置 → 承载形状。最上面是新的「预览」组，共三行。

预期：「当前承载」显示类似 圆盘 · R64 · 44pt · 7 个 · 起点 0°。
若此处显示 —：说明这一行没读到值，把 /var/mobile/Aevon.log 末尾发我。
3

点「预览承载形状（全屏）」

全屏黑底，中间一组图标，周围有虚线圆与枢轴点，顶部三行说明，底部「重播动画」。

预期：图标从中心点扩散出来并逐个放大落位，约半秒；顶部第三行会写图标来源（LaunchServices / 文件扫描 / 占位图标）。
若顶部写着「占位图标」：说明设置进程读不到真实图标，形状仍然正确，但请把这三个字告诉我 —— 下一步就从桌面侧抓图标。
4

点图标

随便点一个图标。

预期：图标轻微弹一下、触发一次轻震，下方浮出 App 名称。
5

换形状对比

右上角 × 关闭 → 把「半圆盘」打开（会自动关掉「圆盘」）→ 再点预览。

预期：只剩上半圆一排 4 个图标，虚线导引弧也一起缩短。再试「直角盘」应只剩 2 个。
若四个开关能同时亮：说明互斥没生效，请回传截图。
6

验证参数真的在起作用

把「半径」拉到 120、「图标宽度」拉到 28 → 回预览。

预期：图标明显变小、离中心更远，数量变多（容量公式跟着半径走）。再打开「任意角度」，在预览里按住拖动 —— 整盘应跟着手指旋转。

回滚：直接覆盖安装 dist/ 里的 0.0.4 包。包 id 相同，偏好不丢。 这两个版本桌面侧完全一致，所以回滚不需要重启。

08

边界与下一步

先说清楚没做的部分
没做原因与计划
枢轴不在浮窗右下角浮窗还不存在。预览把枢轴放在屏幕中心，是为了四种形状都能完整看见；接上浮窗后枢轴改为握把坐标，RingView 不用改。
点图标不启动 App启动需要浮窗窗口与场景层。这一步只做形状，故意不掺进来。
收藏 / 旋转自适应·立即·延迟依赖用户收藏列表与屏幕方向事件，与浮窗生命周期一起做才有意义。
图标缓存每次打开预览都重新枚举。目前实测（iOS 设置进程）耗时写在日志 ring preview … in Nms；若超过 200 ms 再加缓存。
